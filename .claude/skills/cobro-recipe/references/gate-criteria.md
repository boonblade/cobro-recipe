# Gate 기준 — "나중에 다시 만날 문제인가?"

레시피는 **Gate 4점 이상**인 문제에만 만든다. Gate를 통과해도 자동으로 작성하지 않고, 사용자에게 먼저 제안한다.

## 1. 판정 절차

1. **Hard 제외**에 해당하는지 먼저 확인한다. 해당하면 판정을 끝낸다 (점수 계산 안 함).
2. 신호 S1~S7 중 **근거가 있는 것만** 점수에 넣는다. 추측으로 가산하지 않는다.
3. 합계 4점 이상이면 제안 메시지(§4)를 출력한다.
4. 사용자가 승인하면 `recipe.yaml`의 `gate` 필드에 점수와 신호를 기록한다.

## 2. Hard 제외

| 유형 | 예 |
|---|---|
| 오타·문구 수정 | 라벨 문구, 주석 |
| 스타일·레이아웃 미세 조정 | padding 2px, 색상 변경 |
| 리네임·포맷팅 | 변수명 변경, lint 자동 수정 |
| 단순 의존성 버전업 | patch/minor 업데이트 |

예외: 의존성 **breaking change 대응**은 제외하지 않고 Gate로 평가한다.

## 3. 신호와 점수

| # | 신호 | 점수 | 근거 예시 |
|---|---|---|---|
| S1 | 서로 다른 접근을 2회 이상 시도함 | +2 | 되돌린 커밋, 폐기한 브랜치, 세션 중 실패한 시도 |
| S2 | 원인이 증상과 다른 층위에 있음 | +2 | "화면 버그인 줄 알았는데 DB 트랜잭션 문제" |
| S3 | 대안을 비교한 설계 결정이 있었음 | +2 | 방식 A/B 비교, 트레이드오프 논의 |
| S4 | 특정 조건에서만 발생 | +1 | 특정 데이터·사용자·시간대·환경·파일 포맷에서만 |
| S5 | 업무·업종 도메인 지식이 필요함 | +1 | 팩의 `domain_knowledge_examples` (예: 회계 마감 규칙, 재고 할당, 그레이딩) |
| S6 | 해결에 세션 대부분 / 반나절 이상 소요 | +1 | 세션 길이, 커밋 간격 |
| S7 | 다른 화면·모듈·데이터에서 재발 가능성 높음 | +1 | 같은 로직·패턴을 여러 곳이 공유 |

최대 10점. **임계값 4점.**

### 판정 예시

| 문제 | 신호 | 점수 | 판정 |
|---|---|---|---|
| 버튼 padding 2px 수정 | Hard 제외 | – | ❌ |
| 월말 마감 배치에서만 재고 수량이 맞지 않음 (ERP) | S1 S2 S4 S5 S7 | 7 | ⭕ |
| 동시 주문 시 같은 재고가 두 번 할당됨 (웹) | S1 S2 S4 S7 | 6 | ⭕ |
| 특정 엑셀 업로드에서만 한글이 깨짐 | S1 S4 S7 | 4 | ⭕ |
| 패턴 2장 봉제선 벌어짐 (garment-3d) | S1 S2 S4 S5 S7 | 7 | ⭕ |
| API 응답 필드명 변경 대응 | S7 | 1 | ❌ |

## 4. 제안 메시지 형식

```
📒 레시피 후보: <한 줄 제목>
Gate 7점 — S1 시도 2회, S2 원인 층위 다름, S4 월말 배치에서만, S5 회계 마감 규칙, S7 재발 가능
레시피로 남길까요? (예: /cobro-recipe write <commit-range>)
```

- 한 세션에서 같은 문제를 두 번 제안하지 않는다.
- 사용자가 거절하면 그 문제는 다시 제안하지 않는다.
