# 쉬운 설명 가이드 (2층 설명)

모든 scene은 같은 내용을 두 층으로 쓴다.

| 층 | 필드 | 독자 | 분량 |
|---|---|---|---|
| 쉬운 설명 | `plain` | 패턴실·MD·경영진 | **2문장 이내** |
| 기술 설명 | `tech` | 개발자 | **3문장 이내** + 코드 15줄 이내 |

## 1. `plain` 작성 규칙

1. **눈에 보이는 현상**으로 시작한다. ("봉제선에서 옷이 벌어진다")
2. 비유는 **옷·원단·봉제**에서 가져온다. 비유는 `glossary/garment-3d.yaml`에 있는 것을 먼저 쓰고, 없으면 새로 만든 뒤 사전에 추가한다.
3. 영문 약어·코드명·라이브러리명을 쓰지 않는다. (mesh, vertex, transform ✗)
4. 수치는 쓰되 단위를 현업 단위로 쓴다. (mm, cm, 사이즈명)
5. "~때문이다"로 원인을 단정하지 않는다. 원인은 `discovery`에서만 말한다.

## 2. `tech` 작성 규칙

1. 정확한 용어를 쓴다. 비유를 섞지 않는다.
2. 재현 조건을 적는다. (입력, 사이즈, 파일, 버전)
3. 코드는 핵심 15줄 이내. 전체 코드는 `evidence`의 file:lines로 연결한다.

## 3. 좋은 예 / 나쁜 예

| 구분 | 나쁜 예 | 좋은 예 |
|---|---|---|
| plain | BufferGeometry의 winding order가 반대라 culling됨 | 천을 뒤집었더니 옷의 한쪽 면이 사라졌다. |
| plain | 좌표 불일치 이슈 발생 | 두 천의 끝이 4mm쯤 어긋나 있었다. |
| plain | seam ID로 해결함 | 봉제선마다 이름표를 붙이고, 같은 이름끼리 맞춰 붙였다. |
| tech | 좌표가 좀 안 맞음 | Panel A/B의 seam endpoint 간 거리 최대 4.2mm (M, 1:1 scale). |

## 4. 점검 체크리스트
