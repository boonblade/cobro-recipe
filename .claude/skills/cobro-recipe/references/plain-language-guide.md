# 쉬운 설명 가이드 (2층 설명)

모든 scene은 같은 내용을 두 층으로 쓴다.

| 층 | 필드 | 독자 | 분량 |
|---|---|---|---|
| 쉬운 설명 | `plain` | 현업 담당자·경영진 (팩의 `business_readers`) | **2문장 이내** |
| 기술 설명 | `tech` | 개발자 | **3문장 이내** + 코드 15줄 이내 |

## 1. `plain` 작성 규칙

1. **눈에 보이는 현상**으로 시작한다. ("월말 마감 후 재고 수량이 장부와 다르다", "봉제선에서 옷이 벌어진다")
2. 비유는 **독자가 매일 보는 것**에서 가져온다. 레시피 팩의 사전 → `general` 사전 순으로 찾고, 없으면 팩의 `metaphor_source`에서 새로 만든 뒤 사전에 추가한다. ([domain-packs.md](domain-packs.md))
3. 영문 약어·코드명·라이브러리명을 쓰지 않는다. (mesh, vertex, transform ✗)
4. 수치는 쓰되 현업이 쓰는 단위로 쓴다. (건, 원, 초, mm, 사이즈명)
5. "~때문이다"로 원인을 단정하지 않는다. 원인은 `discovery`에서만 말한다.

## 2. `tech` 작성 규칙

1. 정확한 용어를 쓴다. 비유를 섞지 않는다.
2. 재현 조건을 적는다. (입력 데이터, 환경, 파일, 버전)
3. 코드는 핵심 15줄 이내. 전체 코드는 `evidence`의 file:lines로 연결한다.

## 3. 좋은 예 / 나쁜 예

| 구분 | 나쁜 예 | 좋은 예 |
|---|---|---|
| plain (general) | race condition으로 재고 중복 할당 | 두 사람이 같은 좌석을 동시에 예약한 것처럼, 재고 하나가 두 주문에 잡혔다. |
| plain (general) | DB 인덱스 누락으로 풀스캔 발생 | 찾아보기(색인) 없는 책에서 한 장씩 넘겨 찾느라 조회가 느렸다. |
| plain (garment-3d) | BufferGeometry의 winding order가 반대라 culling됨 | 천을 뒤집었더니 옷의 한쪽 면이 사라졌다. |
| plain | 좌표 불일치 이슈 발생 | 두 천의 끝이 4mm쯤 어긋나 있었다. |
| tech | 좀 느림 | 주문 목록 조회 p95 4.8s (주문 30만 건, 인덱스 없음). |

## 4. 점검 체크리스트

- [ ] `plain`만 읽어도 무슨 일이 있었는지 이해되는가?
- [ ] `plain`에 영문 기술 용어가 없는가?
- [ ] 같은 기술 용어에 레시피마다 다른 비유를 쓰지 않았는가? (팩 사전 확인)
- [ ] `tech`에 재현 조건이 있는가?
