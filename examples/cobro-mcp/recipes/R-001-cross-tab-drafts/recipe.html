여러 탭에서 쓴 초안 지키기

한 탭에서 써 둔 메모가 다른 탭에서 메모를 고치면 사라졌다. 탭마다 자기 페이지 메모만 바꾸게 하고, 메모의 페이지 이름표도 보낸 탭이 직접 달게 해서 해결했다.

draft 메시지 처리를 전체 교체에서 페이지 단위 교체로 바꾸고(R177), 새 초안의 page를 전역 s.page가 아니라 메시지를 보낸 탭의 page로 찍으며 교체 대상 id는 유지 목록에서 제외했다(Task 69 B1).

🚩 01 · 문제

다른 탭에서 쓰면 앞 탭 메모가 사라진다

탭 두 개에서 각각 메모를 쓰는데, 둘째 탭에서 메모를 고치자 첫째 탭에 써 둔 메모가 사라졌다.

기술 설명

같은 세션에 연결된 두 오버레이(탭)가 각자 draft 메시지를 보낼 때, 한 탭의 메시지가 다른 탭이 만든 서버 초안을 지운다.

근거: fd91128 CHANGELOG.md 메모: Drafts made in one tab are no longer wiped when you edit a draft in another tab
🔍 02 · 관찰

초안 메시지가 "전부 바꾸기"였다

각 탭은 "내가 가진 메모 전부"를 보내고, 받는 쪽은 그것으로 메모함 전체를 갈아 끼우고 있었다. 둘째 탭은 첫째 탭 메모를 모르니 그 메모 없이 덮어쓴 셈이다.

기술 설명

OverlayMsg 'draft'의 계약이 "status draft인 것 전체 교체"였고, SessionCore.setDrafts(batches)는 draft가 아닌 배치만 남기고 초안을 통째로 교체했다.

근거: dd6596f src/core/session.ts 메모: 수정 전 코드는 dd6596f의 부모 34-35행 dd6596f src/core/types.ts
🧪 03 · 시도

시도 1: 페이지 단위로 바꾸기

메모함을 통째로 바꾸지 않고, 보낸 탭의 페이지 메모만 바꾸게 했다. 탭 쪽도 자기 페이지 메모만 보내고, 받은 목록에 다른 탭 메모를 합쳐 보관하게 했다.

기술 설명

draft 메시지에 page(location.href)를 추가하고 setDrafts(batches, pageUrl)가 samePage인 초안만 교체하게 했다. 오버레이 flushDraft는 현재 페이지 초안만 보내고, state 수신 시 서버 순서대로 병합한다.

❌ 04 · 실패

여는 순서를 바꾸면 이름표가 틀리고 메모가 둘로 는다

리뷰에서 막혔다. 첫째 탭을 열어 두고 둘째 탭을 연 뒤 첫째 탭에서 새 메모를 쓰면, 그 메모에 둘째 탭 페이지 이름표가 붙었고 다음 저장 때 같은 메모가 두 개로 늘어났다.

기술 설명

새 초안의 page를 서버 전역 s.page(마지막에 연결한 탭)로 찍어 라벨이 어긋났다. 같은 id를 다시 보내면 samePage 불일치로 others에 남는 동시에 kept에도 들어가 중복 증식했다(리뷰 Task 69 B1).

🧠 05 · 발견

칠판이 하나뿐이었다

메모를 얼마나 바꾸느냐가 아니라 "이 메모가 어느 탭에서 왔나"를 모르는 게 문제였다. 서버는 회의실 칠판 하나에 마지막으로 들어온 탭 이름만 적어 두고, 모든 새 메모에 그 이름표를 붙이고 있었다.

기술 설명

원인은 교체 범위가 아니라 발신 맥락의 부재였다. setDrafts가 새 초안의 page를 전역 s.page에서 가져와 멀티탭에서 연결 순서에 따라 라벨이 달라졌고, 라벨이 어긋나면 교체 대상 판정(samePage)도 함께 어긋났다.

🛠 06 · 해결

보낸 탭이 이름표를 단다

메모를 보낼 때 탭이 자기 페이지 이름표를 함께 보내고, 서버는 새 메모에 그 이름표를 그대로 단다. 이번에 받은 메모는 이름표와 상관없이 항상 새것으로 바꿔 중복을 막았다.

기술 설명

draft 메시지의 page를 {url, title} 객체로 바꾸고, setDrafts(batches, page)가 처음 보는 초안을 메시지 page로 stamp한다. keptIds에 든 id는 others에서 무조건 제외한다. bridge는 page.url이 문자열일 때만 넘긴다(하위 호환).
